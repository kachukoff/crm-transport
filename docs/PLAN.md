# План дипломного проекта: CRM для транспортной компании

**Стек:** React + Vite + SCSS + i18next (frontend), FastAPI + PostgreSQL + Redis (backend), Docker + Nginx + Docker Compose.

**Монорепо:** `frontend/` + `backend/` + `docs/`

**Срок:** 12 октября 2026 → конец декабря 2026 (~10–11 недель)

---

| Изначально | Скорректировано | Причина |
|---|---|---|

## 1. Сущности (минимальный набор)

- **User** — сотрудник системы (роли: `admin`, `manager`, `driver`)
- **Client** — заказчик перевозки (юр. или физ. лицо)
- **Driver** — водитель (ФИО, права, телефон, статус)
- **Vehicle** — транспорт (госномер, марка, тип, грузоподъёмность)
- **Order** — заказ на перевозку (клиент, маршрут, груз, статус, цена)
- **Route** — маршрут (точка отправления → точка назначения, расстояние)

**Связи:**
- Order → Client (many-to-one)
- Order → Driver (many-to-one)
- Order → Vehicle (many-to-one)
- Order → Route (many-to-one)
- User → Driver (one-to-one, если водитель — тоже пользователь)

---

## 2. Экраны (минимальный набор)

1. **Login** — вход
2. **Register** — регистрация (опционально)
3. **Dashboard** — сводка: активные заказы, свободные машины, водители на смене
4. **Orders** — список заказов + фильтры + карточка заказа
5. **Drivers** — список водителей
6. **Vehicles** — список машин
7. **Clients** — список клиентов
8. **Profile** — профиль пользователя + выход

## 3. Этапы работы

### Этап 0. Проектирование (1–2 дня)

**Цель:** не писать код, пока нет модели данных и макета.

Задачи:
- ER-диаграмма (dbdiagram.io или бумага).
- Список экранов + что на каждом.
- Черновой список API-эндпоинтов.
- Определить роли и права.

**Артефакт:** `docs/er_diagram.png`, `docs/screens.md`, `docs/api.md`.

---

### Этап 1. Статика: HTML + SCSS (1 неделя)

**Цель:** сверстать экраны без логики, понять, как выглядит CRM.

Задачи:
- Свёрстать Layout (sidebar + header + content).
- Свёрстать Login.
- Свёрстать Dashboard.
- Свёрстать Orders (таблица + карточка).
- SCSS: переменные цветов, типографика, отступы, кнопки, формы.

**Артефакт:** `frontend/static/` с HTML-файлами, открываются в браузере.

**Почему так:** React неуверенно — сначала вёрстка без React, потом перенос в компоненты.

---

### Этап 2. React + Vite (1 неделя)

**Цель:** перенести статику в React-компоненты.

Задачи:
- Настроить Vite (`frontend/`).
- Разбить Layout на компоненты: `Sidebar`, `Header`, `Layout`.
- Перенести Login, Dashboard, Orders в компоненты.
- SCSS через `sass` в Vite.
- Пока без роутинга и без API — данные хардкодятся в `mock.ts`.

**Артефакт:** `npm run dev`, экраны переключаются вручную через state.

---

### Этап 3. React Router + Docker + Nginx (3–4 дня)

**Цель:** навигация + запуск фронта в контейнере.

Задачи:
- Установить `react-router-dom`.
- Маршруты: `/login`, `/`, `/orders`, `/drivers`, `/vehicles`, `/clients`, `/profile`.
- `Dockerfile` для frontend (multi-stage: build → nginx).
- `docker-compose.yml` с сервисом `frontend`.
- Nginx: раздача статики + проксирование `/api` (пока заглушка).

**Артефакт:** `docker compose up` поднимает фронт на `localhost:80`.

---

### Этап 4. Backend: FastAPI + Postgres + SQLAlchemy (1.5–2 недели)

**Цель:** живой API вместо хардкода.

Задачи (по порядку):
1. Создать `backend/` с `pyproject.toml` (или `requirements.txt`).
2. `Dockerfile` для backend.
3. В `docker-compose.yml` добавить сервисы `db` (postgres) и `backend`.
4. Каркас FastAPI: `main.py`, `config.py`, `/health`.
5. Подключить SQLAlchemy (async) + Pydantic-схемы.
6. Описать модели: User, Client, Driver, Vehicle, Order, Route.
7. Первые CRUD-эндпоинты для Order и Driver.
8. Настроить CORS.
9. На фронте: заменить хардкод на `fetch` к API.

**Артефакт:** фронт показывает данные из Postgres через FastAPI.

**Важно:** на этом этапе без авторизации. Сначала данные должны ходить.

---

### Этап 5. Alembic — миграции (2–3 дня)

**Цель:** управляемые изменения схемы БД.

Задачи:
- Установить `alembic`.
- `alembic init`, настроить `env.py` под async SQLAlchemy.
- Сгенерировать первую миграцию из моделей.
- Опционально: фикстуры (seed-данные) через скрипт.

**Артефакт:** `alembic upgrade head` создаёт все таблицы.

---

### Этап 6. Авторизация: Redis + сессии + роли (1–1.5 недели)

**Цель:** закрыть API и фронт от анонимов.

Задачи:
1. Добавить Redis в `docker-compose.yml`.
2. Backend:
   - Эндпоинты `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`.
   - Хеширование паролей (`passlib[bcrypt]` или `argon2`).
   - Сессии в Redis (session_id → user_id).
   - Middleware для проверки сессии.
   - Роли и зависимости (`Depends(require_role("admin"))`).
3. Frontend:
   - Страница Login (форма).
   - Страница Register (форма).
   - Страница Profile.
   - Кнопка «Выйти» в Header.
   - Защита маршрутов (`<ProtectedRoute>`).
   - Хранение сессии: httpOnly cookie (лучше) или localStorage (проще).

**Артефакт:** без логина не попасть на `/orders`, роли работают.

---

### Этап 7. TanStack Query + Zustand (3–5 дней)

**Цель:** нормальная работа с серверным состоянием.

Задачи:
- Установить `@tanstack/react-query`.
- Обернуть приложение в `QueryClientProvider`.
- Переписать все запросы к API на `useQuery` / `useMutation`.
- Инвалидация кэша после мутаций.
- Zustand — для UI-состояния (тема, сайдбар, текущий пользователь).

**Артефакт:** загрузки, ошибки, рефетчи — через Query.

**Про Redux:** если препод требует — адаптировать этап, но для этой задачи RTK избыточен.

---

## 5. Правила работы

1. **Один этап — один блок коммитов.** Не смешивать вёрстку с API.
2. **После каждого этапа проект рабочий.** Никогда не оставлять сломанное «на потом».
3. **Сначала концепция, потом код.** Сначала архитектура — потом файлы целиком.
4. **Не расширять scope.** Новые фичи — в `docs/backlog.md`, вернуться после защиты.
5. **Диплом ≠ production.** Работает, защищается, понятно — достаточно.
6. **Docker поднимать с этапа 3.** Не откладывать.
7. **Текст диплома писать параллельно**, начиная с этапа 6.
